Read the joint graph first

A URDF joint places and moves its child link

For each revolute joint, the origin gives the zero-configuration joint frame relative to the parent link; axis is expressed in that joint frame.

\[ {}^{P}T_C(q_i)= \underbrace{T(x,y,z)R_z(\mathrm{yaw})R_y(\mathrm{pitch})R_x(\mathrm{roll})}_{\texttt{origin xyz, rpy}} \underbrace{R_{\hat a_i}(q_i)}_{\texttt{axis xyz}} \]

Record one line per joint

parent link → joint name → child link origin xyz="x y z" rpy="r p y" axis xyz="a_x a_y a_z"

Angles are radians and distances are metres. Normalize the axis before using it geometrically.

Do not copy URDF numbers directly into a D–H table. URDF link frames are chosen by the model author; D–H frames must satisfy a geometric axis/common-normal convention.

Keep geometry and appearance separate

A visual origin moves an STL surface—not a joint axis

Kinematic layer

<joint><origin> and <axis> define how link frames move.

\[{}^0T_{L_i}(q)=\prod_{j\le i}{}^{L_{j-1}}T_{L_j}(q_j)\]

Changing a joint origin changes the robot model and invalidates your D–H comparison.

Visual layer

<visual><origin> registers the mesh’s internal coordinates to its link frame.

\[{}^0T_{\mathrm{mesh},i}(q)={}^0T_{L_i}(q)\,{}^{L_i}T_{V_i}\]

scale changes mesh geometry units; it does not change link kinematics.

A perfectly moving skeleton can carry badly registered meshes. A convincing rendering can also hide an incorrect skeleton. Test both layers.

Mesh-registration task

Repair the displaced links in the altered bundle’s visual origins

Edit only this transform

<visual> <origin xyz="x y z" rpy="r p y"/> <geometry><mesh filename="…"/></geometry> </visual>

Change one degree of freedom at a time. Record the final six values for every repaired link.

1

Set the robot to its zero configuration and identify the first displaced mesh.

2

Correct translation \(x,y,z\), then orientation \(r,p,y\).

3

Move every joint through several angles; the mesh must remain attached to its link.

4

Confirm that no <joint><origin> or axis changed.

A visual edit does not update a separate collision origin. Do not modify collision geometry unless that additional task is explicitly assigned.

Forward-kinematics laboratory

Use the simulation to challenge your model, not merely display it

Kinematic residuals

\[e_p=\|p_{DH}-p_{URDF}\|_2,\qquad e_R=\cos^{-1}\!\left(\frac{\operatorname{tr}(R_{DH}^{\top}R_{URDF})-1}{2}\right)\]
  • Test home plus at least five nontrivial configurations.
  • Clamp the inverse-cosine argument numerically to \([-1,1]\).
  • Report the maximum position and orientation residuals.

Visual-registration evidence

  • Capture the zero pose and at least two articulated poses.
  • Check joint housings, link boundaries, and tool attachment.
  • If landmarks are available, report their mesh-to-link errors separately.

Never use visual overlap as the FK residual.

A constant transform discrepancy suggests a frame-convention error. A configuration-dependent discrepancy usually indicates a wrong axis, sign, row order, or joint offset.
