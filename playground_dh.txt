Similar to playground/building_blocks.html, I want to create a file where students can learn standard D-H parameters.

Here the students can learn the meaning of a,d, alpha and theta between two frames, then there will be rpy xyz from urdf like structure, and students will need to require to build DH parameters from one frame to another, 

Take 3 frames

They will be given tasks:
for example:
Task 1: choose the axis direction (here they can select one of the x, y, z, axis of the frames)
After selection -> good, now because DH parameters assume the axis of rotation is aligned with the z-axis,we will denote these directions as z-axis.
Notice that the rpy xyz and DH parameters will have different frame structure, this does not matter as we are concerned about representing the EE wrt the base, and there are many ways to construct the map. Each map is valid as long as the FK model holds.

Task 2: choose a common normal to Z_1 and Z_2
After selection -> good, this becomes our X_1, as we want to rotate Z_1 about X_1 to align with Z_2

Task 3: find X_2 from Z_2 and Z_3

Now we have everything we require, I will draw the Y-axis that comes from the right hand rule of x_hat \cross y_hat = z_hat

Task 4: rotate about Z_1 to align X_1 to X_2.
Here if there are only two frames, then let X_1 be aligned with X_2 already, or else first construct all common normals. 

Task 5: translate along Z_1 to align X1 and X2 to be coincident or collinear

Task 6: rotate about X_1 to align Z_1 with Z_2.

Task 7: translate along X_1 to to be collinear or coincident with X_2.


Discuss different cases such as:
1. parallel axis
2. need to add offset
3. non-coincident frames that will require translation along Z after.
4. Any other special cases related to the standard D-H
